Скелет, одинаковый для всех модулей IIoT

Если студент держит в голове этот скелет, любой модуль — это «скелет + 2–3 своих функции». Ниже то, что повторяется в каждом документе слово в слово.

1. Старт и сеть

  • Экран запуска 2 с: IoT STATION XX (y=0), WiFi: OK/WiFi: FAIL (y=24), AI: READY/AI: OFFLINE (y=40). XX — номер места.
  • При старте подключиться к Wi-Fi и сделать проверочный запрос к ИИ.
  • Потеряли сеть — переподключаться самим; датчики работают и без сети.

2. Код и экран

  • Пины, пороги, тайминги — именованные константы в начале файла.
  • OLED: только латиница, ≤16 символов, строки y = 0, 16, 32, 48 (в A1 — 0, 14, 28, 42).
  • Тексты и форматы — символ в символ как в задании.
  • main.py на плате, автозапуск. Драйверы не менять.
  • Программа не падает ни при каких условиях.

3. ИИ-сервис

  • secrets.py на плате: WIFI_SSID, WIFI_PASS, API_URL, API_KEY, MODEL.
  • Промпт — константа в программе, содержит данные и формат ответа.
  • Ответ — свободный текст: извлечь значение, проверить; плохое не применять.
  • Ожидание ≤10 с; ошибка → резервный режим; повтор не раньше 10 с; не чаще 1 запроса в 5 с.
  • Журнал: мс,AI_REQ · мс,AI_ANS,значение · мс,AI_ERR,причина · мс,AI_BAD.

4. GitHub

  • Репозиторий WSKZ2026_IIoT_XX, папка модуля: A1/main.py, A1/secrets_example.py.
  • Коммит минимум раз в 30 минут, понятное сообщение: A1: wifi connect.
  • Финал: коммит A1 final + push до конца времени.
  • Нельзя: force-push, удалять историю, трогать папки сданных модулей, класть secrets.py и драйверы.
  • Код в репозитории = код на плате.

Где здесь «искусственный интеллект»

В IIoT-модулях ИИ — это большая языковая модель (как ChatGPT) по OpenAI-совместимому API. ESP32 сама ничего не «думает»: она отправляет числа текстом и разбирает текстовый ответ. В C1 есть второй, настоящий нейросетевой ИИ: модель YOLO на AI-модуле A01-AI распознаёт объекты на камере.

Набор ZL-02B AI+IoT Application Module

Платы, датчики и интерфейсы

Набор производит Wenzhou Zhilong Intelligent Technology (Китай): плата ESP32 и AI-модуль ставятся на общую плату расширения (IO Shield), датчики подключаются кабелями к промаркированным разъёмам.

ESP32-WROOM-32 — мозг устройства

  • 2 ядра Xtensa LX6, до 240 МГц; 520 КБ ОЗУ; обычно 4 МБ флеш.
  • Wi-Fi 2,4 ГГц (b/g/n) + Bluetooth 4.2/BLE.
  • Логика 3,3 В. 5 В на вход GPIO подавать нельзя.
  • АЦП 12 бит: значения 0…4095. Два блока: ADC1 (GPIO 32–39) и ADC2.
  • 4 аппаратных таймера, 3 UART, 2 I2C, 2 свободных SPI, ШИМ на любом выходе.

Что эксперт должен знать про пины

  • ADC2 не работает при включённом Wi-Fi. Поэтому аналоговые датчики висят на GPIO34 (это ADC1).
  • GPIO 34–39 — только вход, без подтяжек.
  • GPIO 6–11 заняты флеш-памятью — не трогать.
  • «Strapping»-пины 0, 2, 5, 12, 15 читаются при загрузке. GPIO12 (ECHO в A1) в HIGH при старте → плата может не загрузиться. GPIO2 (MISO в B2) — тоже strapping.
  • UART0 = USB и консоль Thonny. Для A01-AI используют UART2 (16/17).

Датчики и модули

A1 · MA

HC-SR04 — ультразвуковой дальномер

  • На TRIG подаём импульс ≥10 мкс → датчик излучает 8 импульсов 40 кГц.
  • ECHO держит HIGH столько, сколько звук летел туда и обратно.
  • Расстояние = время × 0,0343 / 2 (см, время в мкс) ≈ время / 58.
  • Диапазон 2–400 см, конус ~15°. Мягкие и наклонные поверхности дают ошибки.
  • Нет эха → драйвер выдаёт тайм-аут или ошибку. Это и есть «OUT OF RANGE».
все модули

OLED SSD1306 128×64

  • I2C, адрес 0x3C. Проверка: i2c.scan() → [60] (60 = 0x3C).
  • Шрифт 8×8 → 16 символов × 8 строк. Кириллицы нет.
  • Рисуем в буфер (fill, text, rect, fill_rect, pixel, line, ellipse), потом show() отправляет кадр.
  • invert(1) — аппаратная инверсия всего экрана (A1, B2).
  • Без fill(0) старый текст остаётся — частая потеря баллов.
A2

PIR — датчик движения

  • Пироэлектрический: видит изменение теплового (ИК) излучения человека.
  • Выход цифровой: 1 = движение. Сам держит 1 несколько секунд (потенциометр времени).
  • После включения ~30–60 с «прогревается» и может давать ложные срабатывания.
  • «Срабатывание» = фронт 0 → 1, а не каждый опрос со значением 1.
A2

Датчик освещённости

  • Фоторезистор в делителе напряжения → аналоговый сигнал на АЦП.
  • Темнеет — значение растёт или падает: зависит от схемы делителя. Поэтому задание говорит «определите на стенде». Закройте датчик ладонью и посмотрите в консоли.
  • АЦП ESP32 шумный и нелинейный → усреднять (в A2 по 4 замерам).
B1

MQ-2 — газоанализатор

  • Полупроводник SnO₂ с нагревателем (5 В, ~150 мА). Чувствует пропан, метан, водород, дым, спирт.
  • Есть газ → сопротивление падает → напряжение и значение АЦП растут.
  • Нужен прогрев: холодный датчик «плывёт». В задании 30 с — учебное упрощение.
  • Проверка — выдохом на датчик (влажность и тепло слегка поднимают сигнал). Открытый огонь и баллончики запрещены.
B1 · MA

WS2812 — адресные RGB-светодиоды

  • В каждом светодиоде свой контроллер; цепочка управляется одним проводом (DI).
  • 24 бита на диод (порядок G-R-B, модуль neopixel переставляет сам).
  • np[i] = (r, g, b) только меняет буфер. Без np.write() ничего не загорится.
  • До 60 мА на диод на полной яркости — можно светить на 60 из 255.
MA

Зуммер BEEP

  • Активный (с генератором): звучит от постоянного уровня, управление Pin.value().
  • Пассивный: нужен ШИМ с частотой: PWM(Pin(x), freq=2000, duty=512).
  • Многие модули включаются нулём (транзистор PNP). Проверка на стенде: value(1) и value(0).
B2 · MB

MFRC522 + карта MIFARE S50

  • Считыватель 13,56 МГц (ISO 14443A), подключение по SPI + вывод RST.
  • S50 = MIFARE Classic 1K: 16 секторов × 4 блока × 16 байт = 1024 байта.
  • Тип карты (ATQA) S50 = 0x0004, драйвер печатает его как 0x0400.
  • Номер (UID) — 4 байта + 5-й байт BCC = XOR четырёх. Пример: 154,63,18,196 → 9A3F12C4, BCC 115 = 0x73.

Почему запись в блоки 3, 7, 11… запрещена

Трейлер хранит ключи и биты доступа. Записать туда 16 байт данных = испортить биты доступа, и сектор навсегда заблокирован. Карта испорчена, баллы потеряны. Ключ по умолчанию у новых карт — шесть байт 0xFF. Авторизация действует на весь сектор: один auth на блок 8 открывает и блок 9.

Порядок общения с картой: поиск SeekCard(0x52) → антиколлизия Anticoll() (получили UID) → выбор select_tag(uid) → авторизация auth(0x60, блок, ключ, uid) → read/write → stop_crypto1(). 0x52 — «разбудить все карты» (WUPA), 0x26 — только незаснувшие (REQA). 0x60 — ключ A, 0x61 — ключ B.

ИИ-сервис: запрос и ответ

POST https://<адрес>/v1/chat/completions
Content-Type: application/json
Authorization: Bearer <API-ключ>

{"model": "<модель>",
 "messages": [{"role": "user",
               "content": "<промпт с данными>"}],
 "max_tokens": 50,

  • Ответ 200: текст в choices[0].message.content.
  • 401 — неверный ключ, 429 — превышен лимит запросов, 5xx — сбой сервиса.
  • temperature: 0 — ответы максимально предсказуемые.
  • max_tokens: 50 — ответ короткий (токен ≈ часть слова).
  • Промпт лучше по-английски и с жёстким форматом: «Reply with exactly one word: LOW, MEDIUM or HIGH».
  • HTTPS на ESP32 съедает ~40 КБ памяти: gc.collect() перед запросом и всегда r.close().

Разбор по модулям

Требования, экраны, ловушки, эталонный код

Чек-лист в каждом модуле — то, что эксперт проверяет на стенде. Код — учебный эталон: прошёл все сценарии в симуляторе на ПК, но на реальной плате его ещё нужно прогнать.

A1A2B1B2C1 AI-IoT:MA / MA1MB

A1 · Ультразвуковой дальномер

Парктроник у въезда в теплицу. Меряет расстояние каждые 200 мс, сглаживает медианой, показывает зону и шкалу. Раз в 10 с отправляет ИИ 10 последних значений, чтобы он сказал: тележка приближается, удаляется или стоит. Основа: опыт 4.15 «Ultrasonic Ranging».

Чек-лист проверки

  • Строки этого модуля на y = 0, 14, 28, 42 (исключение из общего правила). Шкала: рамка x=0, y=54, 122×10.
  • Dist: XX.X cm — один знак после запятой; экран очищается перед каждым обновлением.
  • Измерение по таймеру 200 мс (в журнале ~5 строк в секунду).
  • Медиана 5 последних корректных значений: быстрый взмах рукой не даёт скачка.
  • Некорректно: <2 см, >400 см, ошибка драйвера → OUT OF RANGE на y=24, без расстояния, зоны и шкалы; в буфер не попадает; восстановление само.
  • Зоны: Zone: NEAR <20, Zone: MID 20…50, Zone: FAR >50.
  • Шкала: 100 см и дальше — пустая, 0 см — полная, пропорционально.
  • ИИ: каждые 10 с, 10 отфильтрованных значений с шагом 0,5 с; пока их меньше 10 — не отправлять. AI: ... во время запроса, AI: --- при ошибке или плохом ответе.
  • NEAR и последняя оценка APPROACH → инверсия до смены зоны или оценки.
  • Журнал: 15230,34.5,MID и 15630,-1,OUT + строки AI_*.

Ловушки

Две разные очереди

Буфер медианы — 5 значений каждые 200 мс. Для ИИ нужна отдельная история: 10 значений с шагом 0,5 с. Студенты часто отправляют буфер медианы.

HTTP внутри таймера

Запрос к ИИ длится до 10 с. Если делать его в обработчике таймера, всё зависнет. Таймер только ставит флаг, работа — в основном цикле.

Инверсия «залипает»

После invert(1) надо явно вернуть invert(0), когда условие пропало (и на экране OUT OF RANGE тоже).

Имя метода драйвера

Задание называет только конструктор HCSR04(tri, ech). Как называется метод измерения (distance_cm(), getDistance()…), видно только в файле HCSR04.py — открыть в Thonny или dir(sensor).

A2 · Индукционная лампа

Свет в проходе включается, только когда темно и есть человек. После калибровки устройство знает «нормальную» освещённость. Лампа (на экране это значок-круг) горит HOLD секунд после последнего движения. Раз в минуту ИИ по статистике подбирает новое HOLD от 5 до 30 с.

Чек-лист проверки

  • АЦП: 12 бит (0–4095), ослабление 11 дБ.
  • Калибровка 5 с с обратным отсчётом; порог = 50 % от среднего «в сторону темноты»; в консоли CAL,<среднее>,<порог>.
  • Свет каждые 200 мс, среднее по 4; Light:Normal / Light:Low на y=16 — без пробела после двоеточия.
  • Гистерезис 10 % от порога: на границе состояние не мерцает.
  • Motion:YES / Motion:NO на y=32, заголовок Induction Lamp на y=0.
  • Лампа = Light:Low и Motion:YES. Держится HOLD после последнего движения, новое движение перезапускает отсчёт; стало светло → гаснет сразу.
  • Lamp:ON Ns (сколько осталось) / Lamp:OFF H:Ns (текущий HOLD) на y=48. Круг x 104–122, y 30–48: залит = вкл, контур = выкл.
  • Каждые 60 с: число срабатываний PIR, секунды работы лампы, секунды темноты, HOLD → ИИ → целое 5…30, применяется со следующего включения.
  • Запрос не выключает лампу и не сбивает отсчёт.
  • В консоли только изменения: LIGHT_LOW, LIGHT_NORMAL, MOTION, LAMP_ON, LAMP_OFF, HOLD,<N>.

Ловушки

Направление сигнала

Если в темноте значение растёт, порог = среднее × 1,5. В ярко освещённом зале (среднее 3000) порог 4500 недостижим, лампа не включится никогда. Если падает — порог = среднее × 0,5. Студент обязан проверить направление ладонью до написания логики.

Отсчёт через sleep

time.sleep(10) блокирует всё. Нужен «момент выключения» через ticks_add и сравнение ticks_diff — тогда запрос к ИИ не сбивает таймер.

Свой таймер PIR

PIR сам держит выход в 1 несколько секунд. Значит, «Motion:YES» длится дольше, чем движение, и HOLD фактически считается от спада сигнала.

        else:
            new_low = light_avg < threshold

B1 · Контроль загазованности

Датчик газа в техпомещении. Устройство проходит три этапа: прогрев 30 с, фоновые измерения 60 с, получение порога от ИИ. Затем раз в секунду считает скользящее среднее и при превышении порога мигает красным.

stateDiagram-v2
  [*] --> HEAT: старт + экран запуска
  HEAT --> CAL: 30 с прошло
  CAL --> OK: 60 значений → ИИ → порог AI или DEF
  OK --> ALARM: среднее > порога
  ALARM --> OK: среднее < порог − 20

Чек-лист проверки

  • Прогрев 30 с: Gas, Preheating, Left: N s; тревога в это время не включается.
  • Фон 60 с по 1 значению в секунду: AI CALIB, Left: N s.
  • Порог от ИИ — целое, больше максимума фона и не больше 4000 → Thr: XXX AI. Иначе THRESHOLD_DEFAULT (число объявит эксперт) → Thr: XXX DEF.
  • Консоль: CAL,<среднее фона>,<максимум>,<порог>,<AI|DEF>.
  • Измерение по таймеру 1000 мс, скользящее среднее по 5.
  • Экран: Gas, XXX/4095, строка порога, No Panic / Danger!!.
  • Гистерезис: обратно в норму, только когда среднее < порог − 20.
  • Тревога: все 4 WS2812 мигают красным 1 с / 1 с; в норме выключены.
  • Журнал каждого измерения: мс,значение,среднее,состояние; состояния HEAT, CAL, OK, ALARM.

Ловушки

Порог, которого не достать выдохом

ИИ может вернуть порог 2000 при фоне 400. По правилам он допустим (больше фона, ≤4000), но выдохом тревогу не вызвать. Хороший промпт просит «немного выше шума фона» и передаёт максимум фона.

Забытый np.write()

Цвет присваивается в буфер, а лента меняется только после np.write().

Мигание через sleep

Мигать нужно по времени (ticks_diff от начала тревоги), иначе мигание собьёт период измерений.

B2 · RFID-контроль доступа

Электронные пропуска на картах MIFARE S50. Считыватель находит карту, сверяет UID со справочником users.json, читает имя из блока 8 и счётчик проходов из блока 9, при успехе увеличивает счётчик. ИИ оценивает риск по последним 10 записям журнала.

Чек-лист проверки

  • Пины RST 16, NSS 13, SCK 15, MOSI 32, MISO 2; инициализация Init_spi().
  • Поиск SeekCard(0x52) в цикле с паузой 200 мс; в консоли tag type: 0x0400.
  • Ожидание: Access Control (y=0), Place card (y=24), Risk: … (y=48).
  • UID — первые 4 байта, 8 HEX-символов, верхний регистр: UID:9A3F12C4.
  • users.json на плате: {"9A3F12C4": "ASKAR"}, имя латиницей ≤11 символов; в справочнике одна карта из двух.
  • register() вызывается из консоли Thonny: select → auth сектора 2 ключом A (6 × 0xFF) → блок 8 = имя + пробелы до 16 байт, блок 9 = 0. Экран REGISTER / UID / Write: имя / WRITE OK или WRITE ERROR.
  • Писать можно только в блоки 8 и 9.
  • Доступ: UID в справочнике и имя в блоке 8 совпадает → ACCESS OK, имя, Visits: N, счётчик +1 записан в блок 9. Иначе DENIED и причина Unknown card / Data mismatch.
  • Ошибки Authentication error, Failed to select tag — в консоль, программа работает дальше.
  • После работы с картой stop_crypto1(); результат 2 с; та же карта — не раньше чем через 3 с.
  • ИИ после каждой попытки: 10 последних записей → LOW/MEDIUM/HIGH; Risk: N/A до первой оценки и при ошибке; HIGH → экран ожидания инверсный + мс,ALERT.
  • Журнал: мс,UID,имя,результат,проходы; OK / UNKNOWN / MISMATCH; у отказов вместо имени и счётчика -.
  • Сдать: main.py, users.json, secrets_example.py + зарегистрированную карту.

Ловушки

Как вызвать register() из консоли

main.py крутит бесконечный цикл. Порядок: запустить main.py в Thonny (F5) → Ctrl+C → в Shell набрать register(). Работает, только если в цикле нет голого except: — он ловит и Ctrl+C. Используем except Exception.

Счётчик в 16 байтах

Формат счётчика в блоке 9 не задан. Эталон пишет 4 байта big-endian + 12 нулей (n.to_bytes(4, "big")). Главное — студент может объяснить свой выбор.

Карта вплотную

Карта, прижатая к антенне, ловится нестабильно. Держать в 1–3 см.

C1 · ИИ-камера распознавания объектов

Самый сложный модуль: две программы на двух устройствах. AI-модуль A01-AI видит объект нейросетью и шлёт по UART строку OBJ,bottle,87. ESP32 проверяет строку, ждёт 3 одинаковых подряд, показывает объект на OLED и узнаёт у ИИ-сервиса тип объекта, запоминая ответ в кэше.

  E -- "ACK (GPIO17 → IO7)" --> K
  E -- I2C 0x3C --> O[OLED SSD1306]
  E -- HTTPS --> L[ИИ-сервис: тип объекта]

Чек-лист проверки

  • Провода: «7 6» модуля ↔ «16 17» IO Shield, TX → RX крест-накрест, общий GND. UART 115200, 8N1.
  • LCD: камера QVGA 320×240 в реальном времени, FPS: N жёлтым слева сверху.
  • Модель и 20 классов от экспертов, порог уверенности 0,5 (константа); красная рамка и подпись bottle 0.87; передаётся самый уверенный объект.
  • ESP32 принимает по UART2, проверяет класс по списку и 0…100 %, мусор игнорирует без падения.
  • OLED: AI CAMERA, Obj: класс, Conf: N%, Type: тип; длинное обрезать до 16 символов; NONE → No object (y=24).
  • Новый объект — только после 3 одинаковых сообщений подряд.
  • Нет сообщений >3 с → LINK LOST (y=24); связь вернулась → работа сама продолжается.
  • Новый подтверждённый класс без кэша → ИИ → HUMAN / ANIMAL / TRANSPORT / HOME; кэш-словарь; Type: ... во время запроса; Type: ? при ошибке (без записи в кэш).
  • Во время запроса строки UART не теряются (буфер приёма).
  • Журнал: мс,класс,уверенность,тип; раз в 30 с STAT,person:5,bottle:2 (только ненулевые).
  • Сдать: ai_cam.py, main.py, secrets_example.py; обе программы стартуют сами.

Ловушки

TX в TX

Самая частая ошибка UART — провода не перекрещены или разная скорость. Симптом: тишина или мусор в приёме.

Строка приходит кусками

uart.read() может вернуть половину строки. Копим байты до \n и только потом разбираем.

Буфер на время запроса

За 10 с запроса придёт до ~50 строк × 16 байт ≈ 800 байт. Нужен rxbuf 1–4 КБ, иначе строки потеряются.

#  WSKZ2026 AI-IoT — Модуль B (части B1+B2+B3). RFID-пропуска
#  ESP32 + MFRC522 (SPI) + OLED + карта MIFARE S50
#  B1: SeekCard / NO_CARD   B2: Anticoll + select_tag   B3: auth, write, read
# =====================================================================
import time
from machine import Pin, SoftI2C
import ssd1306
import rc522

# ---------------- Константы ----------------
PIN_RST = 16
PIN_NSS = 13
PIN_SCK = 15
PIN_MOSI = 32
PIN_MISO = 2
PIN_SDA = 23
PIN_SCL = 19
POLL_MS = 200
REQ_ALL = 0x52                       # PICC_REQALL
AUTH_KEY_A = 0x60                    # AUTHENT1A
KEY = [0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF]
BLOCK = 8                            # блок 0 сектора 2 — единственный для записи!
DATA = b"\x01\x01\x02\x03\x04\x05\x06\x07\x08\x09\x0a\x0b\x0c\x0d\x0e\x55"

# ---------------- Оборудование ----------------
i2c = SoftI2C(scl=Pin(PIN_SCL), sda=Pin(PIN_SDA))
oled = ssd1306.SSD1306_I2C(128, 64, i2c)
rfid = rc522.RC522()                                   # СВЕРИТЬ с драйвером
rfid.Init_spi(PIN_RST, PIN_NSS, PIN_SCK, PIN_MOSI, PIN_MISO)
MI_OK = rc522.MI_OK if hasattr(rc522, "MI_OK") else rfid.MI_OK


def show(text):
    oled.fill(0)
    oled.text(text, 0, 0)
    oled.show()


def tag_hex(tag):
    if isinstance(tag, int):
        return "0x%04X" % tag
    return "0x%02X%02X" % (tag[0], tag[1])


def work_with_card():
    """B2 + B3: номер, выбор, авторизация, запись и чтение блока 8."""
    stat, card_id = rfid.Anticoll()
    if stat != MI_OK:
        return
    print("card_id=", card_id)
    if rfid.select_tag(card_id) != MI_OK:
        print("Failed to select tag")
        return
    try:
        if rfid.auth(AUTH_KEY_A, BLOCK, KEY, card_id) != MI_OK:
            print("Authentication error")
            return
        rfid.write(BLOCK, DATA)
        data = rfid.read(BLOCK)
        print("Address 8 data:", data)
        show("READ OK")
    finally:
        rfid.stop_crypto1()


def main():
    while True:
        try:
            stat, tag = rfid.SeekCard(REQ_ALL)
            if stat == MI_OK:
                print("tag type:", tag_hex(tag))
                work_with_card()
            else:
                print("NO_CARD")
                show("NO_CARD")
        except Exception as e:
            print("ERR:", e)
        time.sleep_ms(POLL_MS)

«Пауза основного цикла ≤10 с во время запроса» — а как же «измерение по таймеру»?

Таймер тикает, но работа идёт в цикле, который ждёт ответа. Это прямо разрешено правилом 6 раздела «ИИ-сервис».

A1

При OUT OF RANGE заголовок HCSR04 остаётся?

«Пока в буфере меньше 10 значений» — какой буфер? Медианный хранит 5.

При ошибке ИИ на экране «AI: ---». Инверсия по «последней оценке» остаётся?

Эталон сбрасывает оценку при ошибке, чтобы экран и инверсия не противоречили друг другу. Обратное толкование тоже защитимо («последнее допустимое значение»).

Эталон считает момент подтверждения (3-е сообщение подряд). Если считать каждое сообщение после подтверждения, счётчики растут по 5 в секунду — бессмысленно.
